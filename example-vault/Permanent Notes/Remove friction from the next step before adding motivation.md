## Remove friction from the next step before adding motivation

When a behavior keeps being skipped, the problem is almost never motivation. It is a step: a case to open, a template to find, an approval to wait for. Removing that step changes the outcome for weeks; a motivational push changes it for days.

**Operating rule**: Before asking anyone (including yourself) to try harder, find and remove one step between the trigger and the action.

**Test**: Can I name the step where the behavior usually stops? If yes, remove it first.

**Boundary conditions**: When the step is a deliberate safety check (a code review before a release), removing it trades skipped work for broken work.

**Why it matters**: The default fix for a skipped routine is a pep talk or a reminder; both fade.

**Evidence**: The guitar-on-a-stand experiment in The Small Loop and the approval queue that vanished when decisions were delegated with the task in Teams of Five.

**Your extension**: Our weekly report started arriving on time the week the template opened itself.
